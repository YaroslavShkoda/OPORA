# OPORA — опора

> ПК-приложение, которое записывает, как прошёл день. Не «система жизни», не дашборд из 14 модулей, не ИИ-коуч. Одна кнопка, одна запись, один график.
>
> **Название выбрано 18.11.2026.** Opora — опора. Приложение, которое держит структуру, когда её больше нечем держать.

---

## 0. Правила проекта (обязательные)

1. **Никакого сервера.** Ни облака, ни авторизации, ни внешних API. Всё локально.
2. **Один экран.** Не модули, не вкладки, не настройки. Открыл — видишь день и список.
3. **Финиш через вечер-два.** Не влезает — режем функции, а не срок.
4. **Критерий готовности:** я сам открываю приложение каждый день неделю подряд. Не «написал код», а «пользуюсь».

Причина этих правил: BuyNotBuy застрял не из-за сложности кода, а из-за отсутствия дна. У OPORA дно есть.

---

## 1. Что делает v1

Один экран, сверху вниз:

- **Сегодняшняя запись.** Дата (по умолчанию — сегодня), часы сна, настроение 1–10, одна строка «что было».
- **Кнопка «Сохранить».** Одна запись на дату; повторное сохранение — редактирует.
- **Список последних дней.** Дата, сон, настроение, заметка. Без пагинации, просто последние 30.
- **Мини-график настроения** за месяц. Точки, без осей и легенд.
- **Кнопка «Экспорт».** Выгружает всё в `.md` и `.csv`.

Всё. Больше в v1 не лезет.

### Чего в v1 нет (специально)

- привычек, целей, проектов, тегов;
- нескольких шкал (тревога, энергия, аппетит) — только сон и настроение;
- напоминаний и уведомлений;
- синхронизации, аккаунта, облака;
- ИИ-коуча внутри приложения (ИИ — снаружи, через MCP, см. раздел 5).

## 2. Стек

| Слой | Что | Почему |
|---|---|---|
| Язык | **Rust (stable, edition 2024)** | Один тулчейн на приложение, базу и MCP; на выходе один `.exe` без зависимостей |
| Окно и UI | **egui** через `eframe` | Immediate mode: экран — это одна функция, без HTML/CSS/Node/webview; `cargo run` и всё работает |
| Хранилище | **SQLite** через `rusqlite` (feature `bundled`) | SQLite компилируется в бинарник: не нужен установленный `sqlite3.dll`, синхронный API |
| График | **`egui_plot`** | Родной для egui; точки без осей — 15 строк |
| Даты | **`chrono`** | `Local::now()`, формат `YYYY-MM-DD` |
| Сборка | **`cargo build --release`** | Один файл `target\release\opora.exe`; установщик не нужен, ярлык — вручную |

Тулчейн: `rustup` + stable. На Windows дополнительно нужен линкер: MSVC Build Tools (по умолчанию) или GNU-тулчейн `x86_64-pc-windows-gnu`, если не хочется ставить MSVC. `rusqlite` с `bundled` компилирует C-код SQLite, поэтому C-компилятор обязателен в любом случае.

**Расположение проекта:** `D:\AI\OPORA` (папка проекта; этот файл тоже лежит там)
**Файл базы:** `%APPDATA%\Opora\opora.db`

## 3. Схема базы

Одна таблица. Никаких связей — их нечего связывать.

```sql
CREATE TABLE entries (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  date        TEXT NOT NULL UNIQUE,   -- 'YYYY-MM-DD'
  sleep_hours REAL,                   -- 0..24, может быть NULL
  mood        INTEGER NOT NULL,       -- 1..10
  note        TEXT,                   -- одна строка, свободный текст
  created_at  TEXT NOT NULL,          -- ISO
  updated_at  TEXT NOT NULL
);
```

Почему `date UNIQUE`: одна запись в день, перезапись вместо дублей. Это защита от главной болезни дневников — «накопил три записи за один день и бросил».

## 4. Этапы сборки

Каждый этап заканчивается работающим приложением. Не «половина функционала», а «запускается и что-то делает». У каждого шага есть проверка — без неё шаг не закрыт.

**Этап 0 — окружение и каркас (~1 ч)** ✅ окружение готово
- 0.1 Rust stable + MSVC: `rustup default stable`, MSVC на `D:\VS\BuildTools` (VC.Tools 14.44), Windows SDK 26100 уже был на C:. *Проверка пройдена:* hello-world собирается, `rusqlite` с `bundled` работает.
- 0.2 `cargo init --name opora` в корне `D:\AI\OPORA` — `Cargo.toml` рядом с документами, без вложенной папки.
- 0.3 eframe: окно 720×560, «OPORA», `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` (release-`.exe` не открывает консоль). *Проверка:* `cargo run` открывает окно, `cargo build --release` даёт `opora.exe`.

**Этап 1 — база и запись (вечер 1, ~2 ч)**
- 1.1 `db.rs`: создаёт `%APPDATA%\Opora\`, открывает базу, `PRAGMA journal_mode=WAL`, `CREATE TABLE IF NOT EXISTS`. *Проверка:* тест на `tempdir` — файл создаётся, повторное открытие не падает.
- 1.2 `INSERT ... ON CONFLICT(date) DO UPDATE` — одна запись в день. *Проверка:* тест «сохранил дважды → одна строка, значения новые».
- 1.3 Форма: дата (сегодня по умолчанию), сон (необязательно, 0–24), настроение 1–10 слайдером, заметка, «Сохранить»; при старте подтягивается сегодняшняя запись. *Проверка:* руками — ввёл, сохранил, перезапустил, данные на месте.

**Этап 2 — список (вечер 2, ~1 ч)**
- Последние 30 по убыванию даты; клик по строке подставляет запись в форму. *Проверка:* тест на сортировку и лимит + руками.

**Этап 3 — график (~30 мин)**
- `egui_plot`: точки настроения за 30 дней, без осей и легенд; пустое состояние «пока нет данных». *Проверка:* глазами на реальных записях.

**Этап 4 — экспорт (~40 мин)**
- `.md` (таблица для врача) и `.csv` (UTF-8 с BOM, иначе Excel ломает кириллицу) в `Документы\Opora\`, кнопка показывает путь. Без диалога сохранения и без лишних зависимостей. *Проверка:* файлы открываются, кириллица целая.

**Этап 5 — `.exe` (~15 мин)**
- `cargo build --release`, ярлык на рабочем столе. *Проверка:* запуск двойным кликом из другой папки, данные те же. **Это финиш v1.**

**Этап 6 — MCP (вторая неделя).** См. ниже. Не отдельный воркспейс, а второй бинарь в том же крейте: `src/bin/opora-mcp.rs` + общий `db.rs`.

Если на каком-то этапе затык дольше вечера — этап режется, а не растягивается.

## 5. MCP — вторая неделя, не первая

**Сначала приложение, которое я открываю. Потом MCP.** Иначе данные собирает агент, а приложение не запускается, и смысл теряется.

Архитектура:

```
[OPORA Electron]  ──┐
                    ├──►  opora.db (SQLite, WAL)
[opora-mcp]       ──┘
```

Отдельный процесс, читает и пишет **тот же файл**. Никакого API и сокетов.

Инструменты MCP:

| Инструмент | Что делает |
|---|---|
| `log_entry` | записать/обновить день (дата, сон, настроение, заметка) |
| `query_entries` | записи за период («покажи последние две недели») |
| `stats` | средние, тренд, связка «сон ↔ настроение» |
| `export` | markdown-выгрузка для врача |

Стек: Rust + [`rmcp`](https://crates.io/crates/rmcp) (официальный Rust SDK) + `rusqlite`. 100–200 строк. Регистрируется в конфиге opencode как локальный MCP-сервер.

Смысл: один проект закрывает оба трека — практику кода (приложение) и практику агентов (MCP).

## 6. Для врача

Приложение — не замена шкалам. PHQ-9 остаётся отдельно, заполняется перед приёмом.

Что реально даёт OPORA к приёму: **объективную картину за период**, а не воспоминания. «Последние 30 дней: сон в среднем 6.2 ч, настроение 3.1/10, ниже всего — дни после ночных смен». Это то, что на приёме невозможно вспомнить точно, а по таблице видно за секунду.

Отсюда и `export` в `.md` — чтобы распечатать или показать с телефона.
