# AGENTS.md

OPORA — локальное Windows-приложение-дневник. Одна запись в день: дата, часы сна, настроение 1–10, одна строка «что было». Плюс список последних 30 дней, мини-график настроения и экспорт в `.md`/`.csv`.

Rust + egui/eframe + rusqlite. Один экран, один `.exe`, без сети и без сервера.

**Источник правды о продукте — `OPORA — план приложения.md`.** Если задача противоречит разделу «Чего в v1 нет», не делай её молча — скажи об этом.

## Команды

```bash
cargo run                      # запустить приложение
cargo run --release            # запустить быструю сборку
cargo build --release          # .exe в target\release\opora.exe
cargo test                     # все тесты
cargo test <name> -- --nocapture
cargo clippy --all-targets -- -D warnings
cargo fmt                      # перед любым коммитом
```

Перед словом «готово» — все три зелёные: `cargo fmt && cargo clippy --all-targets -- -D warnings && cargo test`.

Тулчейн: `rustup`, stable, edition 2024. На Windows нужен линкер (MSVC Build Tools или `x86_64-pc-windows-gnu`) и C-компилятор — `rusqlite` с `bundled` собирает SQLite из исходников.

## Структура

```
src/
  main.rs      точка входа, настройка окна eframe
  app.rs       состояние экрана + одна функция update()
  db.rs        открытие базы, CREATE TABLE, CRUD
  entry.rs     struct Entry + валидация
  export.rs    .md и .csv
tests/         интеграционные тесты на временной базе
```

## Код

- Зависимости: `eframe`, `egui_plot`, `rusqlite` (feature `bundled`), `chrono`, `anyhow`, `tempfile` (dev). Новый крейт — только если без него нельзя, и с объяснением зачем.
- Ошибки: `anyhow::Result` насквозь. Своих error-типов в v1 нет.
- Одно соединение `rusqlite::Connection` живёт в `App`. Без пула, без `Arc<Mutex<_>>`, без async-рантайма: egui и rusqlite синхронные.
- Дата на границе с БД — `String` в формате `%Y-%m-%d`; внутри — `chrono::NaiveDate`.
- Имена, типы, API — по-английски. Текст интерфейса и комментарии — по-русски. Комментарий объясняет «почему», а не «что».
- Пример того, как выглядит нормальный код в этом проекте:

```rust
pub fn load_entry(conn: &Connection, date: &str) -> Result<Option<Entry>> {
    let mut stmt = conn.prepare(
        "SELECT date, sleep_hours, mood, note FROM entries WHERE date = ?1",
    )?;
    let entry = stmt
        .query_row([date], |row| {
            Ok(Entry {
                date: row.get(0)?,
                sleep_hours: row.get(1)?,
                mood: row.get(2)?,
                note: row.get(3)?,
            })
        })
        .optional()?;
    Ok(entry)
}
```

## Границы (нарушать нельзя)

- **Никакой сети**: ни `reqwest`, ни телеметрии, ни автообновлений, ни авторизации, ни OpenAI/LLM-вызовов из приложения.
- **Файл базы** — `%APPDATA%\Opora\opora.db`. Тесты работают только с `tempfile::tempdir()`, настоящую базу не трогают никогда.
- **Схема** — одна таблица `entries`, `date` UNIQUE. Новые таблицы и колонки — только по явному запросу.
- **Не добавлять** привычки, цели, теги, дополнительные шкалы, напоминания, синхронизацию, ИИ-коуча.
- **Формат экспорта** не менять без запроса: `.md` распечатывают и показывают врачу.
- Папку `D:\AI\Жизнь` не читать и не менять. В этом проекте живут только файлы OPORA.

## Как работать

1. **Думай до кода.** Сначала перечисли допущения и самый простой вариант. Если трактовок несколько — покажи их, а не выбирай молча. Если проще, чем просят, — скажи.
2. **Простота.** Минимум кода, решающий задачу. Никаких абстракций для одного использования, «на будущее», конфигурируемости и обработки невозможных сценариев. 200 строк, которые помещаются в 50, — переписать.
3. **Хирургические правки.** Менять только то, что просили. Не рефакторить соседний код, не переформатировать чужие строки, не удалять чужой мёртвый код — сказать о нём. Каждая изменённая строка должна объясняться задачей.
4. **Цель и проверка.** Задача формулируется как проверяемый результат: «форма сохраняет запись, после перезапуска она на месте» → `cargo run` + `cargo test`. Цикл до зелёного, а не «вроде работает».

## Готово, если

- `cargo run` открывает окно, и заявленное действие реально выполняется руками.
- `fmt` / `clippy -D warnings` / `test` зелёные.
- Дифф содержит только правки по задаче.
- Закрытый этап отмечен одной строкой в «Журнале» плана.
